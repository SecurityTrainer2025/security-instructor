# تسليم وسائط دورة المرور واختبار الإصدار

24 نوفمبر 2026. الفرع `feat/self-study-traffic-course`. مرجع ما قبل التسليم `d16a3121d78febed605432d43a571f1249d8ad1c`.

## الاستلام

اعتمد المالك المظهر البصري والزي الحالي. أُغلق طلب إعادة إنتاج المشاهد وتغيير الزي. تحقّقنا من مساحة الملفات ومن الفروع والوسوم المرئية في مستودع `SI-Media-Production`. الفرع `transfer/traffic-windows` يحوي حزمة إنتاج Windows وتعريف مهمة النقل. لم تصل ملفات MP4 النهائية أو مرفقاتها. واجهة GitHub الخاصة بالإصدارات رفضت الطلب، لذا لا يمكن استبعاد وجود مرفق غير ظاهر عبر Git.

لاستكمال الاستلام، ضع مخرجات `review-output` في فرع خاص جديد مثل `incoming/traffic-windows-final` في مستودع الوسائط، أو أرفق الأرشيف بهذه المحادثة. نحتاج ملفات `tm1s1` إلى `tm5s2`، لكل منها `.mp4` و`.en.vtt` و`.timing.json`. أرفق بصمة SHA‑256 للأرشيف أو للملفات إن كانت متوفرة. لا تضع مفاتيح أو بيانات متدربين في الأرشيف.

```sh
python3 scripts/verify_traffic_final_media.py --windows-output --media-dir /path/to/review-output
```

يفحص الأمر ترميز الوسائط وأبعادها ومستوى الصوت وفك الترميز، ويطابق حدود ترجمة VTT مع توقيت JSON ومدة الفيديو. أسماء النشر المقابلة لكل شاشة موجودة في `production/traffic/scene-plan.json` في الحقل `staging_filename`. بعد الاستلام، تُنسخ ملفات MP4 وVTT إلى الأسماء المقابلة داخل `frontend/assets/traffic-videos/` مع حفظ توقيت المصدر وملخص SHA‑256. يُضبط الاعتماد للشاشات التي اجتازت الفحص على البيئة التجريبية فقط. تحفظ العملية معرفات الشاشات والتقدم ومعرف الدورة `CRS-TRAFFIC-001`.

## نتائج الاختبارات

| الفحص | النتيجة |
| --- | --- |
| مدقق حزمة Windows | نجح على عشرة ملفات اختبار موجودة مسبقًا. رفض الاعتماد على مجلد التنزيلات لأن المخرجات النهائية العشرة غير موجودة فيه. |
| التسجيل وبريد الوصول | نجح التسجيل وإرسال حمولة البريد إلى بديل محلي لـBrevo وتفعيل رابط من متن البريد النصي مع API معزول. اكتشف الاختبار فواصل أسطر حرفية أفسدت رابط النص، وأُصلحت لدورة المرور فقط. |
| الشهادة والبريد | على سجل إتمام اختبار، نجح مسار إصدار الشهادة ووصل طلب بريد الشهادة إلى البديل المحلي. ظهر سجل الشهادة بحالة إرسال في قائمة الإدارة المعزولة. |
| الإدارة | حُجبت واجهات الإدارة دون تسجيل دخول. نجح تسجيل دخول Chromium إلى لوحة الإدارة وتحميل مؤشر التسجيلات، ونجح جلب تسجيل المرور وقائمة الشهادات من API. |
| التقييمات والتقدم وQR | تبقى أدلة الاختبار المعزول السابق في [تقرير الاختبار](TRAFFIC_IMPLEMENTATION_TEST_REPORT.md). نجح فحص البنية الحالي للتقييمات. |
| تشغيل الوسائط النهائية | مؤجل لحين استلام الملفات. يُفحص بدء التشغيل، والصوت، والترجمة، والتقديم والاستئناف في متصفح كمبيوتر وعلى Android وiOS فعليين. |
| إشارات اليد | أضيفت مراجعة تطبيقية ثنائية اللغة لضوابط الموقع، والتوجيه من شخص واحد، والتوقف عند فقدان التواصل. تحتاج دقة الحركات إلى جدول إشارات الموقع الساري وتقييم مدرب مؤهل. اعتماد المظهر وحده لا يثبت ذلك. |
| بقية الدورات والبيانات | التغيير الوظيفي مقيّد بالمرور، ومحتوى الدورات الأربع ومسارات شهاداتها لم تتغير في هذا التسليم. كل الكتابات كانت على بيانات اختبار في MongoDB محلية معزولة. لم نستخدم أو نختبر سجلات الإنتاج الحية. |
| Render | منع وكيل البيئة الوصول إلى واجهة إدارة Render برمز HTTP 403. فرع خدمة الإنتاج وإعداد Auto-Deploy وDeploy Hooks غير متحققة. لا يوجد نشر أو دفع لهذا التسليم. |

## بوابات الإصدار والتراجع

1. اعتمد بصمة الملفات المستلمة، وافحص الفيديوهات الفعلية على الأجهزة المذكورة، ثم احصل على اعتماد المحتوى التطبيقي من المدرب المؤهل. اختبر أيضًا وصول رسالة حقيقية إلى صندوق اختبار آمن بعد إتاحة Brevo التجريبي.
2. افحص من لوحة Render الفرع المرتبط بكل خدمة، وإعداد Auto-Deploy، وأي Deploy Hooks. سجّل الإصدار العامل حاليًا وأعلام المرور والوسائط قبل طلب الموافقة النهائية. أكّد أن واجهة التجربة وAPI وقاعدة البيانات بيئات منفصلة.
3. إذا ظهر خلل في الوسائط على التجربة، أوقف اعتماد الشاشة المتأثرة كي يعرض المشغّل المعاينة السابقة. إذا ظهر خلل في الشهادة، اضبط `TRAFFIC_CERTIFICATES_ENABLED=false` في الخدمة التجريبية. إذا تعطل مسار الدورة، اضبط `TRAFFIC_PILOT_ENABLED=false` في التجربة واستعد آخر إصدار صالح عبر Render وفق إعداد الخدمة.
4. حافظ على التسجيلات والدرجات والشهادات الصادرة. لا تستعد نسخة قاعدة بيانات لمجرد التراجع عن ملفات الواجهة أو الكود. بعد التراجع، افحص بوابة المرور واستمرار ظهور دورة أخرى ومسار التحقق من شهادتها في بيئة معزولة.
